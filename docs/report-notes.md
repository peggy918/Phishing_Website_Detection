## 階段 1（2026-11-01）正規化、品牌比對、特徵

### 正規化 `app/services/normalizer.py`（→ p.6–7 G2）
規則：去開頭雜字元、補 scheme、scheme／主機名小寫、去 www.、中文網域轉 punycode、去預設連接埠、去追蹤參數（其餘參數保留順序）、`&amp;` 還原、非 ASCII 與空白百分比編碼、保留 fragment（#/login 前端路由）。
- **不變性測試**：8 個政府真實網址 × 5 組追蹤參數（含大小寫 `UTM_Source`）＝40 個組合，正規化結果與特徵都不變；大小寫、www、:443、前後空白、結尾的點也不變；正規化兩次結果相同（冪等）。
- 異常輸入（→ p.16 G7）：空字串、只有空白、`javascript:`、`ftp://`、沒有主機名、主機名含空白（含不換行空白 \u00a0）、超過 4,096 字 → `InvalidURL`。
- 資料中發現：
  - Kaggle 參數分隔符被 HTML 跳脫成 `&amp;`（`amp;id`、`amp;session` 出現在前 25 名參數）→ 還原，否則 `amp;fbclid` 不會被當成追蹤參數。
  - 5 筆網址的路徑或參數含空白（政府 2 筆是 fbclid 值中間斷開）。原本整筆拒絕，改成比照瀏覽器編碼為 %20，只有主機名含空白才拒絕。
  - 政府 6 筆網址路徑含中文（46 號「【現貨供應】…」）→ 統一百分比編碼，否則同一網址兩種寫法長度不同。

### 品牌比對 `app/services/brand_match.py`（→ p.8–12 G3、p.6–7 G2）
依關鍵字長度決定比對方式（5 字以上或含數字：任意位置；4 字：開頭；3 字以下：整個詞），並做同形字正規化（0→o、rn→m）與近似比對（6 字以上純英文、從詞首比、差 1 字以內）。
**迭代過程（以各資料集命中結果調整，適合寫成測試驅動的修正紀錄）**：

| 問題 | 例 | 修正 |
|---|---|---|
| 4 字關鍵字子字串誤中 | line → online | 4 字只看開頭 |
| 漏抓政府大量變體 | onlytoppc24、sharefunpc24 | 含數字的關鍵字任意位置 |
| 5 字關鍵字近似太寬 | onlinetest 的 linet ≈ hinet | 近似只比 6 字以上 |
| 關鍵字是常見英文 | shoppe → shopping、shoppers | brands.yaml 移除 shoppe（版本 2026.11.01-1），改由近似比對抓 shoppe5 |
| 去掉數字後變常見字 | mobile01 → mobile ≈ movie、mozilla | 含數字的關鍵字不做近似 |
| 容許差 2 字太寬 | easycamp ≈ easycard | 一律最多差 1 字 |
| 平台名稱被當品牌 | xxx.hinet.net → 中華電信 | 平台型網域只看子網域 |

最終命中率：政府詐騙 **31.0%**（contains 476、similar 30）；Kaggle 釣魚 1.2%、Kaggle 正常 1.0%；台灣正常網域（非品牌）**0.1%**（只剩 taiching ≈ taishin）；含品牌字的正常網域 14 個中 12 個命中（預期，這就是測試集 C 要測的誤判）。

**白名單風險（階段 3 待決定）**：Kaggle 有 13 筆釣魚網址在品牌官方網域上，12 筆是 `onedrive.live.com` 的檔案分享連結、1 筆是 Instagram 帳號頁。live.com 列在 Microsoft 官方網域，若白名單整個放行，這類釣魚會被判為「未發現風險」→ 使用者可上傳內容的官方網域不能整個列入白名單。

### 安全設計（→ p.14 G5）
- **不連線**：有測試把 socket 連線與 DNS 查詢都換成會失敗，偵測流程照常跑完。
- **管理頁本機限制的陷阱**：cloudflared 跑在本機，Flask 看到的來源也是 127.0.0.1，只檢查來源 IP 會讓外部訪客進得了管理頁。所以帶轉送標頭（CF-Connecting-IP 等）的請求一律視為外部並回 404。複審開放 Tunnel 前就要有這層保護。
- XML 用 defusedxml，拒絕實體膨脹與外部實體（有攻擊字串測試）；檔案上限 5 MB；同一檔案（SHA-256）不重複匯入。
